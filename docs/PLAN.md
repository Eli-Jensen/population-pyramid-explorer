## 0. Executive summary

Recommendation: ship direct metrics on the 42 age-sex shares as the default ("Shape" = ½·L2/σ + ½·per-sex Wasserstein/σ) and run your image-embedding idea as a pre-registered, gated experiment inside M0, not as the architecture. Measured on this corpus today: SigLIP2/DINOv2 cosine correlates with shape distance (ρ≈0.83) but overlaps a shape metric's top-10 only 17–19 % (two shape metrics overlap 42 %); recolouring bars moves an embedding farther than swapping in another country; and any embedding is a function of 42 numbers living on a 5–12-dimensional manifold. The plan still gives "Visual" a real route to the menu: embeddings computed before triplet selection, 32 of 80 human judgments reserved for blend-vs-visual disagreements, paired sign test, pre-registered notch/bulge niche; a negative result is a published deliverable in evals/RESULTS.md.

Big architectural call: fully static. No server, database or vector DB; ~42k × 42 u16 rows brute-forced in the browser (1–2 ms); Svelte 5 + Vite on Firebase Spark; uv/Python build emitting hashed shards. Entity shard (13 KB) + year shard (24 KB) serve the default same-year journey; a ~1.7 MB delta-gzip blob loads only for cross-year and time-shift. v1 ≈ 60 h: M0 data/metrics/embeddings/protocol, M1 country page, M2 twins + opposites (demo-able line at ≈44 h), M3 compare/time-shift/export, M4 evaluation for the record.

Holes found, fixes proposed: Firebase may transparently decompress the .gz blob and break DecompressionStream; the naflex/DINOv2 processors resize away the patch-aligned render unless configured; blob size, bands size and phone timings are estimates; single-rater triplets need repeated items; the four external label sets must be obtained before they can be frozen.

**[v3] Status of those holes in this version:** blob size is now measured (§3.4, 1.63 MB modular-delta gz on the 237-entity subset, ≈1.65 MB byte-transposed at full corpus scale); the `.gz`-extension hazard is removed by design (`.d16z` + explicit content-type + magic-byte sniff + a 10-minute pre-M1 probe on `retiremap-ej`); the HF processors are pinned to the render resolution with asserted output shapes; bands are cut to a 25-point grid and the default table leaves `meta.json`; phone timings and a Worker decision rule are on the M1 smoke list; triplets carry 8 repeated items and a self-agreement floor; the label retrieval is a pre-M0 task with a pre-registered fallback.

## 2. Borrow from populationpyramid.net / skip

Borrow exactly (reason)
- **Representation**: bar = sex-bin / total population, 42 bars sum to 100 %; male left `#4682B4`, female right `#EE7989`; bins `0-4 … 95-99, 100+`, youngest at bottom; % at bar ends. This is the size-invariant vector the metric runs on.
- **Fixed symmetric axis that never moves while scrubbing.** **[v2 — axis default changed]** Default = **"fit entity"**: the smallest of {10, 12, 14, 17} % covering the entity's max bar over all 151 years, computed at build (`entities[].axis_pct`). Measured today on the parquet: 186 entities → 10 %, 47 → 12 %, 1 → 14 %, 3 → 17 % (ARE, GUM, QAT; OMN → 14). Only ARE and QAT exceed 10 % in 2026; p99.9 of all 1.5 M bars = 9.8 % (v1's "12.2 %" was wrong; 0.065 % of bars exceed 10 %, 0.0035 % exceed 12 %). Rationale: the Gulf male bulge is exactly what the metric calls "most different"; clipping it with a `▸14.5%` marker on the page, in every Opposites card and in the overlay contradicts the text. Options in the chart menu: "pin 10 %" (clamp marker for the rare overflow) and "never clip (0–17 %)". Result cards and compare page use max(focal, candidate) fit with an "axis widened" caption. Never per-pyramid autoscale. `test_build.py` asserts the axis distribution (`n10 ∈ [170,200]`, `n17 ≤ 5`) rather than hardcoding v1's wrong quantile.

### 3.3 Normalisation
Per (entity, year): `s42 = [m_0..m_100, f_0..f_100] / T`, `T = Σm+Σf` (thousands). **[v2] Quantise with largest-remainder rounding** so every row sums to exactly 65535 (`share_u16`); assert `np.all(u.sum(1) == 65535)`. `T` kept as float32. No smoothing, no per-bin z-scoring, no per-sex normalisation in storage. **[v3]** The float64 shares are also written to `data/processed/pyramids.parquet` before quantisation; the crosscheck (§3.5) runs against that frame, not the u16 rows.

Features are computed **client-side** (`web/src/lib/math/features.ts`) with a Python twin (`src/pyramid_explorer/features.py`). **[v2] Parity fixture** `evals/fixtures/parity_500.json` is generated by Python **from the exported u16 rows dequantised as `u/65535`** — the exact array JS sees — so |Δ| < 1e-6 on share-derived features and distances is attainable; < 1e-3 on median/mean age (interpolation). A separate test quantifies quantisation itself: Python-from-float64 vs Python-from-u16 features agree to 1e-4 (measured per-bin error ≤ 7.6e-6). Features: median age (linear interp; 100+ as [100,105)), mean age, u15, wa 15–64, o65, o80, child/old/total dependency, base slope s[0-4]/s[20-24], s[0-4]/s[10-14], modal bin, WA sex ratio Σm[20–59]/Σf[20–59], stage ∈ {expansive, constrictive, stationary} + flags {male-skewed WA-SR > 1.3, urn modal bin ≥ 45}. **[v2]** `feat` z-scores are computed over the **same-year country set** (never corpus-wide, which is dominated by projected years), matching `explain.ts`. **[v3] Standardisation rule for any pair (q_y, c_y'), including cross-year results and the compare page:** both members' raw features are z-scored against the **focal (query) year's** country set in scope; the candidate's own year is never used as a reference population. Stated in `explain.ts` and `features.ts`; unit-tested on KOR 2026 / JPN 2005 (§4.4). Hahn-Klimroth classes are computed in Python for eval labels (§4.6).

### 3.4 Outputs **[as-built note 2026-09-04: bands ship as float32 `bands.{sha8}.bin` on the 24-point GRID with an 800 KB budget (measured 594 KB), `bands_default` ≈ 19 KB, and `emb/*.f16` ship for both image spaces per DECISION 4 — CONTRACT AMENDMENTS §F/§G are authoritative where this section differs.]** (`web/public/data/wpp2024/`, **[v2]** every file or directory carries the build hash; `build_data.py` wipes the directory before writing; `/data/**` immutable except `NOTICE` (`max-age=3600`))

**[v3] Corpus blob format (`shares.{sha8}.d16z`).** Deltas are stored **modulo 65536 as Uint16**: `d[r] = (u[r] − u[r−1]) & 0xFFFF` within an entity, with `prev = 0` for row 0 of every entity (so row 0 stores the absolute u16 value and no delta ever crosses an entity boundary). Reconstruction is a modular running sum in a `Uint16Array` — no signed type, no special case; `test_quantise.py` and `math/delta.test.ts` assert byte-exact round-trip on the full corpus and on a synthetic row set containing 0 and 65535. Layout: **byte-transposed** (all low bytes, then all high bytes) before gzip-9 — measured today on the 35,787 real u16 rows (237 countries; aggregates absent from pyramid-econ's parquet): raw u16 3.01 MB (gz 2.34 MB) · modular delta gz **1.63 MB** · zigzag gz 1.59 MB · **delta byte-transposed gz 1.40 MB** · zigzag byte-transposed gz 1.28 MB. Scaled to the ~279-entity corpus (×1.18): delta byte-transposed ≈ **1.65 MB**, plain delta ≈ 1.92 MB. Adopted: modular delta + byte-transposed (the zigzag variant saves 0.12 MB more but reintroduces a signed step; not worth it). The build report records all four sizes on every build. **The file has no `.gz` extension** (§8: Firebase must never be tempted to add `content-encoding`); `lib/data.ts` sniffs the first two bytes — `0x1f 0x8b` → `DecompressionStream('gzip')`, anything else → treat the body as already-inflated (a proxy inflated it) — and validates the inflated length `== n_rows × 84` before decoding. Budget = measured × 1.3 → **≤ 2.2 MB**.

**[v2] 3.4a Percentile calibration.** Same-year distance scale is not stationary (median random-pair L2 = 0.048 in 1950, 0.074 in 2024, 0.039 in 2100), so pooled tables would call every 2090 pair "Close" and every 1950 pair "Far". **[v3] Grid = 25 points everywhere: {0, 1, 2, 5, 10, 15, 20, 25, 30, 40, 50, 60, 70, 75, 80, 85, 90, 95, 97, 98, 99, 99.5, 99.9, 100} (+ one spare slot reserved; stored as u16 value × 1e4).** Bands need only p5/p25/p75/p95; "percentile of d" is linearly interpolated within the grid and reported at 1-point resolution only in the tails where the grid is dense, otherwise rounded to the nearest grid point (the UI says "≈ 62nd percentile"). Tables:
- `same[metric][sex][year]` — random same-year country pairs ≥ 100k, 2,000 pairs per year × 151 years: 151 × 25 × 2 B = 7.5 KB per metric×sex; ~14 combinations ≈ 106 KB.
- `cross[metric][sex][era][decade_of_query]` — pairs (q_y, c_y') with y' drawn under the era mask (`obs` = ≤ last_observed_year OR ≤ current year; `all`), per decade of query year: 14 × 2 × 16 × 25 × 2 B ≈ 22 KB.
- `best[metric][sex][era][decade_of_query]` — distribution of `min_y d(q, c_y)` over random (q, c) — the null for time-shift headlines and `best` matches: ≈ 22 KB.
Total ≈ 150 KB; `export.py` asserts `bands.*.u16 ≤ 200 KB` and `bands_default ≤ 8 KB`. Band function selects the table by |Δy| and era, **not by UI mode** (vitest asserts): Δy = 0 → `same`; else `cross`; time-shift rows and `best` → `best`. Bands: Very close ≤ p5 · Close ≤ p25 · Typical · Far ≥ p75 · Extreme ≥ p95. A y* that lands on the era boundary (e.g. NGA → 2100) is shown as "not reached by 2100", never as a match. σ constants exist for every metric × sex including **σ'_L2 and σ'_W1 for the total-only blend** (v1 omitted σ'_W1, so years would have swamped the L2 term). **[v3]** `visual` gets σ and all three tables only when `build_data.py --emb` is given (§3.6); otherwise the metric is **absent** from the tables (a name→offset index at the head of the file, not zero-filled slots), so the file shape is deterministic either way.

**[v3] Payload budget test (`export.py`), per request class, not per directory:** first-paint set (JS gz + entities gz + meta gz + one entity shard + one year shard + `bands_default`) ≤ 175 KB; any entity shard ≤ 16 KB; any year shard ≤ 32 KB; `shares.*.d16z` ≤ 2.2 MB (measured × 1.3; re-derived from the build report, never hand-edited); `shares.*.u16` ≤ 4 MB; `bands.*.u16` ≤ 200 KB; any `emb/*.f16` ≤ 6 MB; whole `web/public/data/wpp2024/` ≤ 16 MB.

## 4. Similarity engine

### 4.1 Definition of "shape"
Shape = `s42`, the 42-vector of five-year age × sex shares of total population. Size-invariant (by construction); not age-shift-invariant (an older population is a different shape); not sex-swap-invariant (Qatar's male bulge is shape); **[v2] shift-aware, not shift-tolerant**: the CDF term penalises a bulge shift proportionally to years moved (1 bin ≈ 0.24 y, 6 bins ≈ 1.43 y) where L2 is blind to position; the shift-*tolerant* option is `l2s`. Sex ratio counts toward shape by default; "Total only" collapses to s21. Never per-bin z-score; never autoscale the vector.

### 4.2 Default metric `blend` ("Shape")
```
l2   = ‖s42_a − s42_b‖₂
w1s  = 5 · Σ_k (|CM_a,k − CM_b,k| + |CF_a,k − CF_b,k|)   # per-sex cumulative shares; unbalanced, surplus parked at 100+; years
d    = α · l2/σ_L2 + (1−α) · w1s/σ_W1,  α = 0.5;  σ = medians over random same-year country pairs ≥100k at build
```
Why: continuity 0.996; JPN 2024 → ITA, GRC, PRT, PRI, ESP, DEU; NER → MLI, TCD, SOM; QAT → ARE, BHR; USA → NZL, AUS, NOR, GBR; DEU → AUT; KOR → TWN; Qatar most isolated 2024 by 2×. ~1–2 ms over 42k rows (M4 Max; phone numbers pending, §10 M1). Knobs: α (grid 0.3–0.7) and smoothing σ, fit on triplets (§4.6).
**[v2] Documented asymmetry** (About + RESULTS): because surplus mass is parked at 100+, a young male surplus (Gulf) pays ~13 bins × 5 y of transport while an elderly female surplus (Japan 80+) pays almost nothing, and CM and CF both carry the imbalance. The balanced sex-aware alternative already measured (W1 on s21 + λ·Σ w_k|r_a,k − r_b,k|, continuity 0.982, λ = 50 y) is the `advanced` option `w1bal` and a λ candidate in `fit_params.py`. RESULTS reports the top-10 sensitivity of normalising σ by p10 instead of the median (rankings are decided in the p1–p10 regime).

### 4.3 Metric menu **[v2 — trimmed visible set]**
Visible (3): `blend` Shape (default) · `w1` Age-shift distance in years (caveat: ≈ |Δ mean age|, sex-blind) · `l2` Bin-by-bin. Under "advanced": `l2s` Shift-tolerant (Gaussian σ = 1 bin, kernel [.054,.242,.399,.242,.054]) · `hel` Emphasise elderly tail · `feat` Summary statistics · `w1sex` · `w1bal`. Toggle: Sex = Two-sex / Total only (blend → (l2 on s21)/σ'_L2 + w1/σ'_W1). ~~`visual` appears only when `verdicts.visual ∈ {default, menu}`~~ **[superseded by DECISION 4: `visual` is always in the menu, labelled experimental; `meta.verdicts.exposed_visual` says which image space]**; `clr` (Aitchison) stays in Python evals only (zero-clipping on near-empty 95+ bins makes it tail-noise dominated). Every entry has a one-line tooltip.

**Verdict mechanism.** `eval_similarity.py` writes `verdicts[metric] ∈ {default, menu, advanced, lab, rejected}`; the dropdown is built from it. Rules (gates in §4.6): `default` = `blend` unless a challenger passes every gate AND beats blend on the paired triplet test at α = 0.05; `menu` = passes G1 continuity, G2 external labels, G4 outliers, and triplet agreement ≥ 75 % on the common random set; `advanced` = passes G1 + G4 only; `lab` = fails a gate but C1 ≥ 0.8 (URL-only via `?metric=`); `rejected` = C1 < 0.8 or fails G2 badly (class agreement < 0.6) → blob not shipped. **[v3]** Additionally, no verdict may be promoted above `lab` *on triplet evidence* unless the rater self-agreement floor in §4.6 item 8 is met.

2. ### 4.5 Where image embeddings fit — engagement with Eli's idea
Eli's idea, taken seriously: render every pyramid, embed with a chart-literate vision model, retrieve nearest/farthest. It is the zero-feature-engineering baseline, the only route to sketch/screenshot queries, and the natural home for "gestalt" similarity. What was measured today on real renders of this corpus: SigLIP2-base and DINOv2-base cosine correlate with shape distance at Spearman ≈ 0.83 but overlap W1's top-10 by only 17–19 % (the two numeric metrics overlap each other at 42 %); recolouring bars moves a SigLIP2 vector farther from itself (cos 0.897) than swapping in a random country (0.944) while the nearest genuine neighbour sits at 0.994; whitening collapses correlation to 0.15. Literature: LineNet image-only P@10 0.11 vs 0.79 when supervised by the data distance; CLIP non-monotone in bar length; CharXiv/EncQA value-retrieval failures at the few-percent level while adjacent WPP years differ by < 1 %/bin. And any embedding is a function of the 42 numbers already in hand on a manifold with intrinsic dimension 5–12.

**[v2] What changed so the experiment can actually go either way:**
- **Computed in M0, not M4.** Render (2 s) + two models (≈ 3–6 min each on MPS at the v1 settings; **[v3]** re-timed at the settings below and recorded in `image_embeddings.md`) run in M0 alongside the numeric metrics, so every candidate exists before a single triplet is selected. Verdicts are still only finalised in M4 after the human triplets.
- **Render resolution aligned to patch size** (v1's 336 px "one patch row per bar" matched no SigLIP2 checkpoint — HF has base-patch16 at 224/256/384/512 + naflex only): `canon2` for SigLIP2 = `siglip2-base-patch16-naflex` at **336² = 21 × 16 px** rows; for DINOv2-base (patch 14) = **294² = 21 × 14** (HF `Dinov2Model` interpolates position embeddings natively). `render.py` asserts `H % 21 == 0 and H // 21 == patch` per model; `emb/*.meta.json` stores (model, resolution, patch, style hash); `embed_images.py` refuses to run if the on-disk renderer hashes differently. Style: white bg, zero gap, M left steelblue / F right #EE7989, fixed ±17 % (never clips, corpus max 16.1 %), no text. `canon1` = total-only mirrored T/2 grey (sex-blind space). PCA-64 without whitening, Float16. Models Apache-2.0 only; CLIP ViT-L/14 (MIT) only if results are ambiguous; so400m, DINOv3 (attribution clause), jina-clip-v2 (NC) excluded.
- **[v3] The HF image processors must not undo the alignment** (with defaults they do: `Siglip2ImageProcessor` resizes to fit `max_num_patches=256` ≈ 256 px, and `AutoImageProcessor` for `facebook/dinov2-base` resizes to 256 then centre-crops 224 — so neither model would ever see the 336²/294² render). `embed_images.py` therefore constructs the processors explicitly: naflex with **`max_num_patches=441`** (21 × 21 patches of 16 px = 336², exactly the render; note that naflex was trained at the 256/576/1024-patch budgets, so 441 is in-distribution but an untrained budget — recorded in `image_embeddings.md` as a caveat, with 576 = 384² as the fallback resolution if the 441 result looks degenerate), and DINOv2 with **`do_resize=False, do_center_crop=False`** (equivalently `size={'height':294,'width':294}`, `crop_size` 294). Asserted on the first batch and written into `emb/*.meta.json`: naflex `spatial_shapes == (21, 21)` and `pixel_attention_mask.sum() == 441`; DINOv2 `pixel_values.shape[-2:] == (294, 294)`. A unit test feeds one render through each processor and compares the recovered tensor to the PNG pixels (max abs diff ≤ 1/255 after un-normalising) to prove no resampling happened. The factorial invariance diagnostic below runs only after this assertion passes, so it measures the render, not resampling artefacts.
- **Invariance is a diagnostic, not a gate.** The shipping safeguard against style drift is the render-hash guard, so cross-style invariance is not a property the product needs; the v1 gate bundled four nuisances and was guaranteed to fail. Now: a **factorial** design on 2,000 pyramids — colour, gap (0 vs 2 px), resolution (±32 px, processor re-pinned per size), aspect (1:1 vs 4:3), each alone — reporting cross-style self-match rank and top-10 Jaccard per factor, so RESULTS says *which* artifact leaks. Reported, not gated.
- **Falsifiable gates for `visual`** = G1 continuity, G2 external labels, and the blend-vs-visual triplet subset with a paired test (§4.6). **Pre-registered niche**, written in `evals/image_embeddings.md` before the run: the ≥ 15 triplets whose anchors carry a detected cohort notch/bulge (§4.4 step 4 detector on the 2024 set); visual "wins the niche" only if it beats blend there by the paired sign test at α = 0.05. No other post-hoc niche is admissible.
- **Pre-registered predictions** (hypotheses with numeric gates, not conclusions): SigLIP2 C1 < 0.95; DINOv2 C1 < 0.95; class agreement ≥ 0.6 for both; neither beats blend on the paired test; expected verdict `lab`. If either passes, "Visual" ships as `menu`, captioned "experimental: what a vision model thinks looks alike".
- **Not doing**: API embedders, vector DB, autoencoders/contrastive training, text tower, `/lab` routes, de-renderer. **Documented future path** (About): screenshot queries = de-render to 42 numbers, then the numeric index; sketch-to-query (v1.1, no ML).

### 4.6 Evaluation protocol (`tests/test_protocol.py` gated; `scripts/eval_similarity.py` → `evals/RESULTS.md` + `evals/verdicts.json`)
**[v2] Two kinds of label sets, kept apart:**
- **Frozen external labels (`evals/labels/`, committed before M0's first eval run; commit hash written into RESULTS.md):** (a) Korenjak-Černe, Kejžar & Batagelj 2015 (Population Studies) cluster memberships for 2006 — transcribed from the paper; (b) Hahn-Klimroth 2025 rule classes computed from the data (metric-independent); (c) populationpyramids.org's published expansive/stationary/constrictive thresholds (median age < 25 / 35–40 / 40+); (d) RIETI's CHN 2020 → JPN ≈ 1990 window [1985, 1995]; (e) Yoshida et al. 2019 epitome sequence (World 2015 → {IND, EGY, MAR, DZA…}; World 2050s → {URY, PRI}).
- **[v3] None of these is in hand yet** — they are cited from abstracts and summaries, the 2015 paper is paywalled and may give 2006 memberships only as figures, and the 2006 clusters were computed on WPP2006/2008 estimates that differ materially from WPP2024's 2006 figures for some countries (Nigeria, DR Congo, China revisions). **Pre-M0 retrieval task (≈ 1 h, `scripts/fetch_labels.py` + manual transcription; the `arxiv` and `papers` MCP servers are installed):** fetch the open-access Korenjak-Černe et al. 2008 *Informatica* paper (more likely to list countries per cluster), arXiv 2508.03788 (Hahn-Klimroth 2025) and arXiv 1810.00210 (Yoshida et al.), and the RIETI page; extract membership/rule tables with page references into `evals/labels/*.yaml`; record the **data vintage** per label set in each file's header and in RESULTS.md. **Pre-registered fallback ladder, decided before any metric runs:** if 2015 memberships are unobtainable, G2(a) uses the 2008 lists; if no per-country lists exist at all, G2(a) is demoted to "reported" and G2(b)/(c) carry the gate; for the vintage mismatch, G2(a) is scored on the WPP2024 rows *and* a sensitivity row drops the ≤ 10 countries whose 2006 total differs by > 10 % between vintages (list fixed from the Demographic Indicators file before scoring). M0 code does not start until `evals/labels/` is committed with its fallback status filled in.
- **Hand-edited groups (`evals/canonical_groups.yaml`) are regression tests for blend, never verdict gates.** Kept as written in v1 (aged-Europe, Sahel, Gulf-migrant, Anglo-Nordic, {KOR, TWN}, {CHN, THA, CUB}); the JPN-from-East-Asia and VNM-from-fast-transition removals are recorded in RESULTS.md as *findings* about the metric, not label choices.

Gates and reports:
1. **G1 Continuity** (self excluded): C1 = P(NN is same country, |Δy| ≤ 1) ≥ 0.95; C5 ≥ 0.99. **[v2]** Reported separately for 1950–2023 and 2024–2100 (projections inflate C1); the gate applies to the observed span.
2. **G2 External labels**: (a) Korenjak-Černe 2006 clusters — same-year 2006 top-10 class agreement ≥ 0.7 and normalised P@k (or the fallback status above); (b) Hahn-Klimroth class agreement — fraction of same-year top-10 sharing the query's class ≥ 0.85 (promoted from "reported" to gate); (c) stage agreement ≥ 0.9; (d) CHN 2020 → JPN best year ∈ [1985, 1995]; (e) epitome sequence: ≥ 3 of the named countries in top-5 for World 2015 and both of {URY, PRI} in top-5 for World 2055. **[v2] P@k = hits / min(k, |G|−1)** everywhere; groups with |G| ≤ 3 report rank-of-first-member / MRR instead.
3. Regression (reported): canonical groups mean normalised P@5 and MRR; time-shift windows KOR 2050 → JPN [2040, 2060], KOR 2024 → JPN [2000, 2010], IND 2024 → CHN [1995, 2005].
4. **G4 Outliers**: isolation I(x) = mean d to 5 nearest same-year countries ≥ 100k; QAT, ARE, BHR, KWT in 2024 top-10; floor off → MCO, VAT enter top-10.
5. Method agreement: top-10 Jaccard matrix over 200 random queries.
6. **[v2] Opposites test**: for 20 random 2024 anchors at β = 2, the 5 opposites cover ≥ 3 Hahn-Klimroth classes and ≥ 3 UN regions; β = 0 reproduces plain farthest-k exactly; per-entity dedupe holds in cross-year modes.
7. Image diagnostics (reported): factorial invariance per §4.5; dynamic range (p1–p99 cosine spread); LineBench-style P@10 vs blend pseudo-labels (agreement with the incumbent, labelled as such).
8. **Human triplets** (`/eval/triplets`, dev-only route, not footer-linked; localStorage + copy-JSON → `evals/triplets.json`, committed). **[v2] Design pre-registered in `evals/protocol.md` before selection:**
   - Question shown, fixed: *"Which of A or B is more similar in shape to the anchor?"* (data facet; the perceptual "looks more alike" phrasing is deliberately not used for promotion, and the choice is recorded). **[v3]** If Q3's default is taken, the 32 blend-vs-visual items are re-asked in a second 15-minute sitting with "looks more alike" (sides re-randomised); that result is published as a finding and never used for promotion.
   - n = 80 unique, stratified: 32 (40 %) where A/B = top-1 of blend vs `visual` (best image space by G1) on the same anchor; 38 where A/B = top-1 of two disagreeing numeric metrics; 10 "most different" items (A/B = top-1 opposite under two metrics; question: "which is more *different* from the anchor?"). Anchor = random 2024 country ≥ 1M; text-free, identical-scale renders; Eli picks A / B / tie.
   - **[v3] Reliability design (single rater):** `select_triplets.py` appends **8 duplicates** of earlier items (drawn 4 from the blend-vs-visual stratum, 3 numeric, 1 opposite) with **A/B sides swapped**, placed ≥ 30 positions later → **88 items, ≈ 75 min**. Side assignment is randomised per item; item order, side map and response time are recorded in `triplets.json`. RESULTS reports **self-agreement** on the 8 pairs (ties count as disagreement unless both are ties). **Pre-registered rule: if self-agreement < 75 % (< 6/8), no verdict may be promoted above `lab` from triplet evidence**, and the numeric α/σ/λ fit is reported but the shipped defaults stay at α = 0.5 / σ = 1 bin. An optional second rater (partner/friend, ~30 min on a 40-item subset) is reported as inter-rater κ and never pooled into the test.
   - **Agreement is defined pairwise for every metric**, including ones whose top-1 is neither A nor B: a metric agrees with a judgment if it ranks the chosen item closer to the anchor than the other. Ties are excluded from tests, reported as counts. Duplicates are excluded from the sign tests (first response counts).
   - **Decision** = paired sign test (McNemar) on discordant triplets at α = 0.05; MDE stated up front: with 32 blend-vs-visual triplets one side must win ≥ 22 of the non-tie discordant items (≈ 69 %) to be called; with 80 total the numeric-vs-numeric comparisons resolve gaps ≥ ~20 points. Marginal CIs are reported but never used for verdicts.
   - α and smoothing σ (and λ for `w1bal`) grid-searched with leave-one-out on the numeric triplets; the fit uses none of the blend-vs-visual items.
Acceptance for `default`: G1, G2, G4 pass and ≥ 80 % agreement on the common set. For `visual` → `menu`: G1, G2, G4 pass and (beats blend on the 32-item paired test OR wins the pre-registered notch/bulge niche) — otherwise `lab` or `rejected` per §4.3; **[v3]** both routes also require the self-agreement floor.

## 5. "Most different" semantics
"Most different" = farthest under the active metric, **diversified**, over the same candidate mask as "similar". Plain farthest-5 from Japan 2026 (real corpus, two-sex) = CAF, QAT, TCD, NER, SOM; total-only = CAF, TCD, SOM, NER, MLI.
```
cand  = mask (§6); in cross-year modes dedupe cand per entity first (farthest year per entity)
pool  = min(ceil(0.25·|cand|), 2000) farthest from q
S = [argmax d(q,·)]
while |S| < k: S += argmax_{x∈pool∖S} [ d(q,x) + β · min_{s∈S} d(x,s) ]
```
**[as built, 2026-09-04 — presets re-calibrated on the real corpus]** Diversity is three labelled presets — strict (β 0) · **balanced (β 0.5, default)** · **spread (β 2)** — `div=` stays numeric in the URL (`search.DIV_PRESETS`). Measured over the 199 country anchors ≥ 100k at 2026: the diversity term saturates early because the pool is already the farthest quartile, so the plan's β 2 / β 4 pair picked the same five countries for 85 % of anchors; mean top-5 Jaccard vs strict is 0.66 at β 0.5 and 0.37 at β 2, and the two presets differ on 99 % of anchors. Japan 2026 balanced (two-sex): CAF, QAT, TCD, NER, OMN #27; spread: CAF, QAT, ARE #24, GNQ #44, SAU #50. **Diversity is over shape distance, not class or region**: for an old anchor the pool is entirely young 'pyramid'-class Sahel/Gulf countries, so no β yields ≥ 3 Hahn-Klimroth classes or ≥ 3 UN regions (mean regions ≈ 2 at every β; RESULTS.md β-sweep table) — product copy must not promise regional variety; a region/subregion cap is the v1.1 option below. **[v2] Raw rank never hidden**: each card shows "#7 farthest" + distance percentile, a faint strip under the cards lists the strict top-k ("strictly farthest: QAT, CAF, NER, SOM, TCD"), and a headline sits above: "Japan 2026 vs Niger 2026: farther than 99.6 % of random pairs". Cards explain "different because" (metric decomposition + features). Also: focal distinctiveness ("more isolated than 91 % of countries this year"), a home-page "Most unusual pyramids of {year}" isolation ranking, and "most different within own history" as one row under the trajectory panel. Subregion-cap alternative → v1.1.

## 11. Risks & mitigations
1. Cross-year results dominated by converged projections → era default observed + nowcast; projections opt-in with badge + visible count chip; time-shift table as the productive cross-year view; **[v3]** projected-year queries flip the default with an inverted chip (§6).
2. Microstates / aggregates pollute results → 100k floor and countries-only defaults, `is_micro`.
3. Opposites degenerate to one regime → MMR balanced preset, per-entity dedupe before MMR, strict strip so the raw list is always visible; §4.6 item 6 tests it.
4. Default metric disagrees with Eli's eye → triplets in M4 with a paired test; α/σ/λ fit; menu always available; a challenger takes the default only with numbers; **[v3]** rater self-agreement floor stops noise from promoting or demoting anything.
5. Percentile bands lie → per-year `same`, per-decade `cross`/`best` tables; band chosen by |Δy| and era; **[v3]** 25-point grid keeps them at ≈ 150 KB with p5/p25/p75/p95 exact.
6. Users read "similar" as "same development level" → decomposed reasons + features; About states shape ≠ development.
7. **[v3] Spark bandwidth**: light visit ≈ 170 KB, engaged ≈ 2.3 MB; blob only on cross-year; immutable cache; pre-compressed (measured, budget = measured × 1.3); quota documented with both numbers; fallback (Blaze + $5 alert, or Cloudflare Pages mirror) decided before any outage.
